# VERSIONS.md: pinned stack

**Verified:** 2026-08-20; every version below was checked against its official source that day (links at the bottom); later changes carry their own dates.
**Policy:** no upgrades during the benchmark; the one change, the NVIDIA driver on 2026-09-24, is recorded in its row.
**Machine (surveyed 2026-08-21):** Windows 11 (build 26200) + WSL2 2.7.8 with Ubuntu 24.04.4 / ROS 2 Jazzy; RTX 2080 Ti (11 GB); NVIDIA driver 610.88 at the survey, **616.92 since 2026-09-24** (row below). **Isaac Sim 6.0.1 installed at `C:\isaacsim`**. **v1**, the predecessor project ([sim-nav-benchmark](https://github.com/d1mitrios/sim-nav-benchmark)), provides the reused assets: world generator, 25 seeded world manifests + maps, mission/batch runners, metrics logger, odometry-noise publisher, analysis/plot suite and the tuned `nav2_params.yaml` (v9; v8 is the archived pre-fix default); its local run data is not included here. Bridge topology as in v1: Isaac on Windows, ROS 2 Jazzy in WSL2, deliberately on **NAT** networking with unicast FastDDS initial-peer profiles on both sides (`sim/fastdds_win.xml` on Windows, `~/.ros/fastdds.xml` in WSL pointing at host 172.19.80.1).

## The decision that drove the pins

**Pegasus Simulator has no Isaac Sim 6.x release.** The latest is v5.1.0 (2025-10-26), strictly paired to Isaac Sim 5.1.0: its docs state each release is *"NOT compatible with older versions of Isaac Sim"*, and Isaac 6 support exists only as open, unanswered issues (#131, Mar 2026: extension fails to load on Isaac 6; #143, Jun 2026: support request).

The first plan was to install Isaac Sim 5.1.0 side-by-side with the existing 6.0.1 (zip install, no conflict) and pin the entire project (both embodiments, including the wheeled control re-runs) to 5.1.0: running ground on 6.0.1 and aerial on 5.1.0 would confound the comparison, and the wheeled control is re-run under the pinned versions rather than recycling v1 numbers. Isaac 5.1.0 does not run on this machine's driver (note 11), so on 2026-08-23 the stack was **re-pinned to Isaac Sim 6.0.1 with a local Isaac-6 port of Pegasus** (note 2).

## Notes

1. **The GPU is below official minimum for every candidate.** Official minimums: Isaac 4.5.0 = RTX 3070 / 8 GB; Isaac 5.1.0 = RTX 4080 / 16 GB; Isaac 6.0 = RTX 4080 / 16 GB. The RTX 2080 Ti appears in none of these tables. Empirically it runs v1 on Isaac 6.0 at 0.35–0.55× real time, so this is an accepted, documented risk: headless runs, modest fidelity, budgets defined in **sim time**, overnight batches.
2. **Pegasus runs on Windows-side Isaac 6.0.1 (2026-08-23).** The probe proved it: extension loads, vehicle spawns, Play runs clean through `dc_shim`. PX4-in-the-loop flight was verified the same day: takeoff, stable hover, land (`docs/INSTALL_PEGASUS.md`, A4). The fallbacks (native Ubuntu dual boot, a ground-only benchmark) were not needed. Isaac inside WSL2 is not possible (v1: "no WSL2 Vulkan").
3. **Pegasus ↔ PX4 boundary (direction read from Pegasus's own launch tool, 2026-08-23):** Pegasus is the TCP **server** (listens on 4560); **PX4 is the client** that connects out to the simulator. The link therefore runs WSL→Windows: launch PX4 with `PX4_SIM_HOSTNAME=172.19.80.1` (the host's vswitch address, same one as v1's fastdds.xml peer) and make Pegasus listen on `0.0.0.0:4560` instead of localhost. `kit.exe` already holds a firewall allow from v1. Networking otherwise stays exactly as v1 left it (NAT, no mirrored mode). **Validated in flight 2026-08-23.** The real blocker on this machine was **ESET Endpoint Security**: a permanent inbound allow rule for 172.19.80.0/20 was required; a Windows Firewall rule alone was insufficient.
4. **OpenVINS Jazzy support = an unmerged PR.** The fork commit is pinned, not a moving branch.
5. **No 6.0→5.1 port (after the re-pin, 2026-08-23):** with the project on 6.0.1, v1's own version, worlds, harness, publishers and configs are reused as they stand. The wheeled control is still re-run fresh; v1's numbers are never recycled.
6. **Findings of the version check:**
   - It is not only Isaac 6.0 that raised the bar above the 2080 Ti: 5.1.0 already lists RTX 4080 as minimum, and even 4.5.0's minimum (RTX 3070) exceeds a 2080 Ti: the card has been "below spec but working" all along.
   - "Prefer whatever v1 already runs" points at Isaac 6.0.x, which Pegasus cannot drive. The two preferences conflict; resolved first in favor of *newest Isaac with a Pegasus release* = 5.1.0, then by the re-pin to 6.0.1 with the local port (notes 2 and 11).
   - Pegasus v5.1.0 brings PX4 SITL 1.14.3: re-verified. (PX4 upstream stable is meanwhile v1.17.0, May 2026; irrelevant, the pin follows Pegasus.)
7. **Alternative considered, rejected:** Isaac 4.5.0 + Pegasus v4.5.1: same below-minimum GPU reality, older docs branch, Ubuntu 20.04/22.04-era with no 24.04/Jazzy story, and an open compatibility issue against v4.5.1 (#119, ArduPilot-side; PX4 unaffected). 5.1.0 dominates.
8. **Not independently verified:** FUEL's ROS version (assumed Noetic-era like FALCON); the exact minimum Windows driver for 5.1.0 (moot: the machine already runs 6.0.1).
9. **Lidar, resolved by the re-pin (2026-08-23):** the plan of 2026-08-21 was "RTX lidar if it works on 5.1.0". Staying on 6.0.x, where RTX lidar is broken (v1's finding), its fallback applies: **v1's custom PhysX-raycast publisher remains the single lidar model for both embodiments.** No RTX smoke test needed. Published v1 numbers are unaffected: they are never recycled.
10. **v1 worlds are 2.5D prisms, geometry confirmed (2026-08-21):** 20×20 m arena; partition walls **and** furniture all 2.0 m tall; no ceiling. Consequences: the 2D frozen map is geometrically valid at any height below 2.0 m, so the quadrotor at its flight altitude faces the *same* obstacle geometry as the wheeled robot; there is no "overfly the furniture" regime in these worlds (any difference between the vehicles comes from footprint/dynamics through doors and coverage rate, not overflight); above 2.0 m the world degenerates to free space. Flight altitude is therefore **fixed at 1.2–1.5 m**; the in-sim check is in `docs/INSTALL_PEGASUS.md` (A5).
11. **Isaac 5.1.0 is unrunnable on this machine's Windows (evidence, 2026-08-23):** startup crash in `rtx.scenedb.plugin` ~15 s in, reproduced twice, on driver 610.88. Known upstream incompatibility of 5.1.0 with the 595.x+ driver branches (maintainer-confirmed; validated drivers: 580.88 Windows / 580.65.06 Linux), while Isaac 6.0 requires ≥ 595.97. The two driver windows are disjoint: no single Windows driver serves both. This forced the re-pin. The unpacked `C:\isaacsim-5.1.0` (~30 GB) is not used.
