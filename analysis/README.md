# analysis/

Every metric is computed against simulator ground truth: the Isaac side logs the
true pose out of band (10 Hz CSV, both clocks, never a ROS topic), the runners log what the
stack believed and claimed, and the scripts here join the two by wall time.

| Script | What it does |
|---|---|
| `verify_missions.py` | One tour's verdict: joins `missions_<seed>_<ts>.csv` with the run's ground truth (`*_gt_<seed>_<ts>.csv`) by wall time; a claim (SUCCEEDED) is a **real arrival** when the truth is within `ARRIVE_M` = 1.5 m of the goal, a **false arrival** beyond it; prints the belief error at every claim and a clock check |
| `plot_tour.py` | One tour over its frozen map (`--map`; default the world's map in `worlds/maps/`): truth, belief, goals coloured by verdict, the belief at each claim, the quadrotor's IMU impacts (the wheeled robot's IMU file has a header only: no impact marks) |
| `plot_explore.py` | One exploration run: the final frozen map over the true geometry, tracks, frontier goals and results, coverage and belief error against policy time |
| `summarize_arms.py` | The three arms' batches in one table (`aerial` from `--aerial runs/raw/batch`, `wheeled` on the shared A* executive from `--wheeled` / `--wheeled-dir runs/raw/wbatch3`, the Nav2 reference `wheeled_nav2` from `--wheeled-nav2 runs/raw/wbatch2`, `''` leaves it out; `runs.csv`: embodiment × world × budget, the frozen map's coverage, real / false arrivals out of the world's goals, attempts, the quadrotor's impacts, the exploration's end) and per budget (`budgets.csv`: mean / min / max real arrivals over the worlds, false arrivals, mean coverage), plus `success_vs_budget.png` and `coverage_vs_budget.png`; only `FINAL` tries count, a missing phase is listed, never guessed. `--goals N` keeps each tour's first N goals in file order (default 6; `0` = all; the goals run in file order, so the first N of a longer tour are exactly the shorter tour). With `--goals 0` it reproduces the aerial batch's table (2026-09-26: 26 / 42 / 57 / 64 real arrivals, one false, impacts 101 / 72 / 52 / 26); with the default 6: 33.3 / 45.0 / 63.3 / 68.3 %, no false arrival, impacts 56 / 39 / 21 / 12. A claim whose own belief (`claim_x`, `claim_y`) was beyond `ARRIVE_M` of the goal is **void** (Nav2 1.3.12's `isGoalReached` bug, the wheeled 013 `tour_b5` g01 / g02 and 016 `tour_b10` g01–g03), neither real nor false, and each tour is scored over its goals less the void ones (`goals_scored`); the Nav2 arm (`wheeled_nav2`) with the default 6: 33.3 / 33.3 / 33.3 / 31.7 % of 60 / 60 / 58 / 57 goals, false 1 / 1 / 1 / 0, void 0 / 0 / 2 / 3; the wheeled arm on the executive (`wheeled`, 2026-10-02): 27 / 26 / 27 / 35 real of 60 (45.0 / 43.3 / 45.0 / 58.3 %), false 1 / 0 / 0 / 0, no void, coverage 136 / 171 / 204 / 246 m² |
| `compare_footprint.py` | The footprint sensitivity check on the wheeled arm: the benchmark batch (`--base runs/raw/wbatch2`, the two circles of the predecessor's v9 Nav2 configuration for the body) against a batch run with the true outline (`--variant`, `policies/nav2/nav2_params_polygon.yaml`: the variant batches `runs/raw/wbatch_fp_full`, the default, and `runs/raw/wbatch_fp_test`; `--variant ""` with `--worlds` measures the benchmark batch alone) on the variant's worlds, per world and phase from the `FINAL` tries: coverage, real / false / void arrivals of the first `--goals` goals, the longest still stretch, the sim-seconds the collision monitor's stop zone held the robot (episodes of its Nav2 log, read in the log's line order; a tour is measured over its kept goals' attempts only), the goals lost to a freeze (a goal not reached whose every attempt ended inside a still stretch ≥ 60 sim-s the zone held for most of its length, whatever the result code but `204`), the true body's contact (box + wheels within 0.01 m of the manifest geometry) and the body model each run's own params copy and log show; a run whose model did not load as written is flagged. Output `footprint_compare.csv` in `--out` (default `analysis/results/`; not one of the committed tables). On the benchmark batch alone (all ten worlds, 2026-09-30): 47 of the 240 goals lost to freezes in 15 of the 40 tours (002 / 004 / 005: 37 of 72), the stop zone holding the robot 12 290 sim-s, the true body in contact in 20 of the 50 runs (its first rule, a TIMEOUT and ≥ 400 sim-s, missed 002's frozen tours: 14 of 66 on 2026-09-28) |
| `goal_outcomes.py` | Every tour goal of the three arms (the first `--goals`, `FINAL` tries; the batch options as `summarize_arms.py`) in one outcome class: `real` / `false` / `void` by the claim, `frozen` (wheeled, `compare_footprint.py`'s rule), otherwise the end of the goal's last attempt (the two arms on the executive, `aerial` and `wheeled`, by the executive's reason: `impact` / `no_path` / `blocked` / `contact`, and `other` for `too_narrow`, `odom_lost`, `amcl_lost` or `timeout`; `wheeled_nav2` `no_path` 208 / `off_map` 204 / `timeout` / `other`; `frozen` for `wheeled_nav2` only), `not_run` for a goal never sent; and the wheeled robot's contact from the ground truth (the true body within 0.01 m of the geometry: episodes, samples < 2 sim-s apart merged, and seconds, up to goal N's last attempt; the quadrotor's measure is its IMU impacts, `summarize_arms.py`). Outputs `goal_outcomes.csv`, `outcomes_by_budget.csv` / `.png` (one panel per arm), `wheeled_contact.csv` (both wheeled arms, an `arm` column); the chart groups the classes for display only (the report's Figure 2: verified arrival, not reachable on the explored map = `no_path` + `off_map`, failed on the way = `blocked` / `contact` / `timeout` / `other`, collision abort, frozen by the safety stop, false claim, void hatched), the CSVs keep the classes. With the default 6 (2026-09-30): aerial real 126, impact 47, no path 55, blocked 8, contact 4; Nav2 arm real 78, false 3, void 5, frozen 47, no path 29, off the map 18, timeout 56, other 4, contact episodes 9 / 2 / 12 / 8 at b1 / b2.5 / b5 / b10; on the executive (2026-10-02) real 115, false 1, no path 18, blocked 94, contact 10, other 2 (`too_narrow`), contact episodes 40 / 31 / 46 / 43 (3 126 sim-s) |
| `collision_sources.py` | Where each robot's collisions on the shared executive happened (`--aerial runs/raw/batch`, `--wheeled runs/raw/wbatch3`, the first `--goals`, `FINAL` tries): every IMU impact of the quadrotor, counted as `summarize_arms.py` counts them, and every contact episode of the wheeled robot, merged as `goal_outcomes.py` merges them, each at the robot's true position with the nearest piece of the manifest (outer wall, partition, furniture), whether the frozen map the tour used contains that geometry, the error of the executive's belief against the truth, the attempt and goal it fell in, and for the wheeled robot the motion in the 3 sim-s before it and the part of the body that touched. Output `collision_sources.csv` in `--out` (default `analysis/results/`), the counts per budget printed. With the defaults (2026-10-02): the quadrotor's 56 / 39 / 21 / 12 impacts struck geometry missing from the map 47 / 31 / 10 / 10 times (98 of 128); the wheeled robot's 40 / 31 / 46 / 43 episodes touched geometry the map contains 8 / 12 / 16 / 24 times, 52 of these 60 with the belief within 1 m of the truth (median 0.06 m): 40 at door frames and 12 at furniture, 42 while driving, 40 with a corner or a wheel, during 39 goals of which 20 were not reached; its scored tours drove 419 / 435 / 493 / 628 m |
| `plot_lidar_check.py` | The raycast lidar's samples against the manifest geometry (after any lidar change) |
| `plot_vio_drift.py`, `vio_to_csv.py`, `data/`, `vio_drift_seed20260723001.png` | The monocular VIO's drift against the truth (installation step A6, `docs/INSTALL_PEGASUS.md`; the record behind the VIO's initialization settings and the switch to lidar odometry): `vio_to_csv.py` records the VIO's poses, `plot_vio_drift.py` draws the figure from `data/` |

The batch runners write `explore.png` / `tour.png` and `verdict.txt` into every run directory.

`results/` holds the benchmark's tables and figures (2026-10-02, from `runs/raw/batch`, `runs/raw/wbatch3`
and, as the reference arm, `runs/raw/wbatch2`): `summarize_arms.py`, `goal_outcomes.py` and `collision_sources.py` with their defaults.
Regenerate from the repo root (all three need the run data in `runs/raw/`; without it they stop and write nothing):

```bash
python3 analysis/summarize_arms.py && python3 analysis/goal_outcomes.py && python3 analysis/collision_sources.py
```
