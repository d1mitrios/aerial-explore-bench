# missions/

Frozen-map goal missions: the phase after exploration. The map frozen at a budget is
loaded, a fixed goal set is flown serially, every arrival the stack *claims* is later
checked against simulator ground truth (never visible to the stack). Same goal sets for
both embodiments. The quadrotor's **exploration** runner (FRONTIER3D) lives here
too, because it is the mission executive's follower driven by the shared frontier rule
over the live `slam_toolbox` map; it produces the frozen maps the missions are flown on.

| File | What it is |
|---|---|
| `make_goals.py` | Deterministic goal sampler: 10 goals per world from the ground-truth manifest, rooms served round-robin by floor area, 0.6 m clearance from obstacles, 0.9 m from walls, 2 m spacing (and from the spawn); `rng = default_rng(seed)`. Writes `goals/goals_<seed>.csv` (+ `--plot`: `goals/goals_<seed>.png`) |
| `goals/goals_<seed>.csv`, `goals/goals_<seed>.png` | The goal set of each world: `mission,room,x,y` (g01…g10, tour order = file order), and its overview plot (`make_goals.py --plot`). Committed, identical for both embodiments |
| `gridmap.py` | Frozen map loader (ROS map_server YAML/PGM), lethal inflation by the planner radius, 8-connected A* with an octile heuristic and a proximity penalty near obstacles, NavFn-style goal tolerance, line-of-sight carrot for pure pursuit (tolerates the first 0.25 m of a line that starts inside the inflation band; without any visible point the carrot is half a lookahead ahead *along* the path, never the next cell), path tangent, raw-map free width and the narrowest width within a look-ahead along the path (the executive's yaw axis and narrow-passage detector). The executive's `--unknown free|lethal|wall` selects how unexplored cells are treated (`wall` = impassable but not inflated: the exploration mode, where the goals sit at the edge of the known space). Also a live-map constructor (`from_occupancy`, the mapper's `OccupancyGrid` classified with map_server's trinary thresholds), `known_free_area()` (the coverage measure), `save()` (map_server trinary PGM + YAML, the checkpoint format) and `dijkstra()` (path length to every cell, the frontier metric) |
| `frontier.py` | The FRONTIER3D selection rule, shared by both embodiments, pure numpy: frontier cells = known-free cells of the *raw* map with an unknown 8-neighbour (on the inflated map a doorway's frontier would lose its width and the rooms behind it would never qualify), 8-connected clusters ≥ `min_cells` (10 = 0.5 m), goal = centroid pulled into admissible free space within 1 m, selection = nearest goal by Dijkstra path length with unknown impassable (to the nearest reachable cell within the planner's 0.5 m goal tolerance), goals in slots between known obstacles narrower than `min_passage_m` skipped, every attempted goal blacklisted within 0.5 m (a reached frontier normally dissolves; one that survives its own visit is an unresolvable sliver) |
| `batch_aerial.sh` | The aerial arm unattended: per world one exploration + one tour per frozen map, every run with a fresh Isaac (headless, `sim/launch_a7.ps1` through the WSL→Windows interop) and a fresh PX4 (daemon mode), the odometry chain and the localizer behind the manual recipes' gates, the runner supervised (wall timeout; simulator liveness from `isaac_status.txt`), a clean teardown (runner by SIGTERM = land + manifest, scripts by SIGTERM = their own teardown, PX4 and its startup script, Isaac by its stop file then the reaper until no Isaac process is left), the verdict / figure per run. Link test before the first launch (`sim/link_probe.ps1`: a listener in Isaac's python on Windows 0.0.0.0:4560, a connect from WSL; ok / dropped / refused / port_in_use): a blocked link stops the batch before it starts; a run without a PX4 heartbeat writes `link_diag.txt` (both sides' sockets on 4560) and re-tests the link, and a link found down stops the batch (exit 3). `--link-check` runs only the test. Resume: every attempt in its own directory `<seed>/<phase>/try<k>/` (never renamed: Windows refuses to rename a folder while a file in it is held open); a run whose policy clock started and that did not end in an ERROR or lose the simulator gets `FINAL` and its phase is skipped from then on; setup failures, ERRORs, a dead simulator or a user interrupt are followed by a new try (2 per batch run). Keeps Windows awake (`sim/keep_awake.ps1`). `--smoke` = world 008, 1-minute budget, 2-goal tour; `--dry-run` lists done / pending phases. Outputs `runs/raw/batch/<seed>/{explore,tour_b<budget>}/try<k>/`, `batch.log`, `status.csv`, `link_probe.txt` |
| `cli_check.py` | Pre-flight check: every parameter the executive reads must be defined by both command lines (the executive's and the explorer's); run before every batch |
| `mock/` | Offline harnesses (kinematic PX4, raycast lidar on the frozen map, localizer and mapper mocks, 20× speed) driving the real command lines; see `mock/README.md` |
| `aerial_slam.sh` | Mapping bring-up for one exploration flight (WSL): `slam_toolbox` `online_async_launch.py` with `policies/slam/slam_params.yaml` (the predecessor's, with `transform_timeout` 1.0, set for the VIO's latency and kept), any stale mapper or AMCL killed first (never two localizers on `/map`), node gate, `/scan` check, DDS hygiene on stop; foreground until Ctrl+C. Log `runs/raw/slam_<seed>_<ts>.log`. Needs the odometry chain for the odometry TF (`aerial_odom.sh`, or `vio_odom_bridge.py --pose-topic /pose` with OpenVINS) |

## Mission CSV (one row per attempt)

`mission, goal_x, goal_y, attempt, result, wall_s, sim_s, epoch_start, epoch_end,
sim_start, sim_end, claim_x, claim_y, path_m, reason, px4_x, px4_y`

`result` ∈ SUCCEEDED · ABORTED · TIMEOUT (the predecessor's vocabulary); `reason` explains
an abort: `no_path` (planner refused on the frozen map), `path_end` (planner tolerance
moved the goal beyond the claim radius),
`odom_lost` (no odometry pose for `--vio-stale-s` = 1.5 *simulation* seconds: wall gaps of 1–2 s are routine at RTF 0.15; `vio_lost` in runs before 2026-09-24), `blocked` (no progress along the path for `--blocked-s` sim seconds: a safety hold or slide that does not resolve), `amcl_lost` (the odometry moved more than `--amcl-stale-m` = 3 m since the last
`/amcl_pose`; AMCL updates every 0.15 m of motion and never while holding, so the criterion is
displacement, not time), `odom_diverged` (the belief faster than `--max-belief-speed` for a second; `vio_diverged` before 2026-09-24), `too_narrow` (the lidar's lateral clearances sum to less than `--min-passage` 0.70 m: a slot, not a doorway; the vehicle backed out first), `impact`, `contact`, `no_estimate`. `claim_*` is the belief at the claim; `sim_*` is the PX4
lockstep clock; `px4_*` is PX4's own position at the row's end, a diagnostic column,
never used by the executive. The verdict comes from
`analysis/verify_missions.py`, which joins the rows with the Isaac ground-truth CSV by
wall time and applies ARRIVE_M = 1.5 m.

## Run MANIFEST (JSON)

`seed, run_id, wall_start/end, params` (every command-line parameter), `map`, `goals`,
`events` (connected, parked_imu, takeoff_cmd/done, dart_out/back, odom_ready (lidar) or
vio_initialized (vio), else odom_retry / ODOM_INIT_FAIL, anchor with the odom→map transform, amcl_initialized (with the first
correction) or AMCL_INIT_FAIL, policy_clock_start, narrow_passage / narrow_passage_end (one pair per doorway), safety_hold / safety_hold_end, impact (`where=settle` when it began in a settle), settle_standoff, odom_lost, odom_diverged, amcl_lost, tour_stopped, return_home,
home_reached or home_abort, land; each with wall time and the PX4 clock), `results` (the CSV rows),
`summary`, `status`.

## Exploration outputs (`runs/raw/explore_<seed>_<ts>/`)

`frontiers_<seed>_<ts>.csv`, one row per frontier attempt: `frontier` (f01…), `goal_x,
goal_y`, `path_m` (the Dijkstra length that selected it), `size` (cells), `clusters`
(candidates at selection), `result` (SUCCEEDED · ABORTED · TIMEOUT), `reason` (the
executive's vocabulary above), `wall_s, sim_s, epoch_start, epoch_end, sim_start, sim_end`,
`coverage_m2` (known-free area after the attempt).

The run MANIFEST adds `budgets_min`, `checkpoints` (one per budget: `budget_min`, `t_sim`
since the policy clock, `map` = the frozen `map_b<budget>.yaml` relative to the repo,
`coverage_m2`, `frontiers` left, `final` = true when a run that ended early gave its last
map to this budget, `size`, `origin`) and the events `frontier_selected` (k, goal, path
length, cluster size, candidates, coverage), `frontier_done` / `frontier_failed`,
`checkpoint`, `checkpoint_no_map`, `too_narrow` / `retreat_done` / `retreat_blocked`, `explore_done` (`reason` ∈ budget · complete ·
exhausted · impacts · a fatal estimator reason), `NO_MAP` (no map within `--map-wait-s`),
`MAPPER_POSE_FAIL` (the pose gate on `/pose` did not pass). `summary` = reason, frontiers
attempted, `t_sim`, final coverage, blacklist size. The mission phase loads
`map_b<budget>.yaml` through `aerial_amcl.sh <seed> <map.yaml>` and the executive's
`--map`; coverage-vs-budget and the success curves come from these files (`analysis/`).

## Odometry of the quadrotor

```
Isaac (Windows)                          WSL2
  /scan (lidar_link, sim stamps) ──► lidar_odom_bridge ──► /scan_odom (misses → 0) ──► rf2o ──► /odom_rf2o, TF odom→base_link
  /a6/imu (impact / liftoff metrics) ──► executive         │ static TF base_link→lidar_link
```
Since 2026-09-24 the odometry the localizers and the executive consume comes from the lidar
(rf2o range-flow, scan to scan); the camera is off in benchmark runs (`AEB_CAMERA=0`).
Until then the source was OpenVINS through `vio_odom_bridge.py` (`--odom-source vio`
keeps that path).

## Localization stack for the exploration phase

```
  /scan ──────────────────────► slam_toolbox (online_async, mapping) ──► /map (latched) ──► explorer (frontiers, A*)
  TF odom→base_link (rf2o) ──►        │
                                      └──► /pose (map frame) ──► explorer belief (correction ∘ odometry)
```
The same chain as the mission phase with the mapper in the localizer's seat: `/pose` is
`slam_toolbox`'s corrected pose (`PoseWithCovarianceStamped`, map frame, one per processed
scan), consumed exactly like `/amcl_pose`. The predecessor's exploration used the same
mapper and parameters with wheel odometry.

## Localization stack for the mission phase

```
  /scan ──────────────────────► nav2 AMCL ──► /amcl_pose ──► executive
  TF odom→base_link (rf2o) ──►      ▲
                                    └── map_server (the exploration's frozen map; worlds/maps for tests)
```
The executive's belief in `amcl` mode = `T_map_odom ∘ p_odom`, with `T_map_odom` derived
from each `/amcl_pose` against the odometry pose of the same stamp (what nav2 publishes as
the map→odom TF), so the belief moves with every odometry pose and is corrected at every
AMCL update. The predecessor's chain is identical with wheel odometry in place of rf2o.
